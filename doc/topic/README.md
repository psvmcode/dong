# 专题文档

> 本目录按**主题**组织，一个主题一份文档，就某一点讲透为止。
> 适合已经了解模块全貌、想深入理解某处设计取舍时读。

---

## 与场景目录的区别

| 目录 | 组织方式 | 回答的问题 |
|---|---|---|
| [`../scenario/`](../scenario/README.md) | 按**模块**横向铺开 | 这个模块整体长什么样 |
| `doc/topic/`（本目录） | 按**主题**纵向深挖 | 这一点到底为什么这么设计 |

建议的阅读顺序：先看 `../scenario/` 建立整体认识，再回到本目录按需深挖。

## 文档清单

### [跨境支付业务专项学习](crossborder-payment.md)

从业务背景、领域概念讲到状态机与风控判定，含完整实操命令与实测数据。

配套代码 `src/main/java/com/dong/crossborder/`，接口前缀 `/api/cross-border`。
建表语句见 [`../../db/schema.sql`](../../db/schema.sql) 中 `cross_border_*` 开头的表。

适合：想搞清楚跨境支付每个环节为什么这么设计。

### [跨境支付 Java 后端面试准备（零基础版）](crossborder-interview-prep.md)

面向**没有支付业务背景**的 Java 后端，把领域知识补到能应对面试的程度。

写法刻意啰嗦：每个术语第一次出现都会解释，每个结论都会给「为什么」，
关键地方给时间线推演和生活类比。

适合：准备跨境支付岗位面试。

## 说明

两份文档都围绕跨境支付，是因为这个模块的业务深度远超其它模块——
它涉及资金安全，任何一个环节的设计失误都是真金白银的损失，值得单独成文。

其它模块如果后续也需要专项展开，同样放在本目录下，
命名沿用 `<模块名>-<主题>.md` 的形式。
