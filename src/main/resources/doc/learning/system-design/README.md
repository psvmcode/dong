## 答题方法

### 通用的四步

```
1. 澄清需求        不要一上来就设计，先问清楚场景和量级
2. 容量估算        算出 QPS、存储量，用数据驱动后面的选型
3. 方案设计        从简单方案开始，逐步指出瓶颈并优化
4. 讨论取舍        主动说出方案的代价，以及什么情况下要换方案
```

**面试考的不是「记住标准答案」，而是这个思考过程。**

### 三个通用武器

不管什么设计题，这三个思路基本都用得上：

| 武器 | 说明 | 用在哪 |
|---|---|---|
| **缓存** | 用空间换时间，扛读流量 | 短链的跳转、秒杀的商品详情 |
| **异步/削峰** | 用 MQ 把瞬时高峰摊平 | 秒杀的下单、以及各种写操作 |
| **分层拦截** | 越早拒绝无效请求越省 | 秒杀的核心思路 |

### 一条主线

**先想清楚「瓶颈在哪」，再谈优化。**

很多设计题的答案不是「加机器」，
而是找出那个真正的瓶颈点（通常是数据库），
然后用缓存、异步、分桶等手段把压力从瓶颈上移走。
