## 怎么用这份文档

**不要背代码，要背「识别特征」。**

看到题目后：

```
1. 读题 → 判断题型（对照模板文档的「总原则」）
2. 套模板 → 写出框架
3. 处理边界 → 空输入、单元素、越界、重复元素
4. 验证 → 用手写的小例子走一遍
```

**第 3 步是大多数人失分的地方**——
模板会背，但边界条件一错就全盘皆输。

## 复杂度速查

| 复杂度 | 典型场景 | n=10⁶ 时大约 |
|---|---|---|
| O(1) | 数组随机访问、哈希 | 瞬间 |
| O(log n) | 二分、平衡树 | 20 次操作 |
| O(n) | 单循环 | 可接受 |
| O(n log n) | 快排、归并、堆排序 | 可接受 |
| O(n²) | 双重循环、冒泡 | **超时**（10¹² 次） |
| O(2ⁿ) | 无剪枝的穷举 | **必然超时** |

**做题时的判断**：

| 数据规模 | 允许的复杂度 |
|---|---|
| n ≤ 30 | O(2ⁿ)（回溯/穷举） |
| n ≤ 10³ | O(n²) |
| n ≤ 10⁵ | O(n log n) |
| n ≤ 10⁶ | O(n) 或 O(log n) |

**看到 n=10⁵ 写双重循环，一定超时**——
这时要么用哈希表降到 O(n)，要么用排序后双指针。

## 常见失分点

| 失分点 | 正确做法 |
|---|---|
| 不确认输入输出就开写 | **先问清边界情况**（空、负数、重复） |
| 整数溢出 | `mid = left + (right-left)/2`，不要用 `(left+right)/2` |
| 回溯忘记撤销选择 | `path.removeLast()` |
| 结果集直接 add 引用 | 要 `new ArrayList<>(path)` |
| 滑动窗口该用 while 用了 if | 收缩是**循环**，不是判断 |
| 0-1 背包正序遍历 | 必须**倒序**，否则物品被重复用 |
| TopK 用错堆 | **求大用小堆** |
| 链表删头节点 | 用 **dummy 节点** |

## 一句话

**模板解决「会不会」，边界解决「对不对」。**
面试里写出能跑的模板只拿一半分，边界和异常处理才是区分度。
