## 核心结论

**能不用分布式事务就不用。**

很多时候所谓的「分布式事务需求」，其实是**服务拆分不合理**造成的——
两个操作本来就该在同一个服务、同一个库里。

**决策顺序**：

```
1. 能不能合并成本地事务？        ← 最优解
2. 能不能接受最终一致 + 对账？    ← 90% 的场景到这里
3. 实在不行才上 TCC / Saga
```

**对账是最后一道防线**：
不管用什么方案，资金相关系统都要定期比对两边数据，
发现不一致就告警并补偿。这与 [`scenario/crossborder.md`](../../scenario/crossborder.md)
里的对账设计是同一个道理。
