## bug 修复：登录后 /api/auth/me 403（同日）

- 现象：登录输入正确账号密码报 403，刷新页面又能进系统（token 已存 localStorage，路由守卫放行）
- 根因：dong-auth 自身 SecurityConfig 只放行 login/refresh/register，`/me` 被 `authenticated()` 拦截；实际上 Controller 自己解析 JWT、网关也已校验，不应再拦
- 修复：`/api/auth/**` 全部 permitAll（与 dong-system 的处置一致）
- 验证：`/me` 经网关和 4173 均 200；登出后同 token 访问 `/me` 返回 401 revoked（黑名单机制仍有效，未破坏安全）
- 经验：**带 spring-boot-starter-security 的服务必须显式配置 SecurityFilterChain**，JWT 统一由网关校验，下游服务一律 permitAll

### 二次追查（同一 403 的真正根因，已修复）
- 修完 dong-auth 后用户浏览器仍 403。用 playwright-core + 本机 Chrome 无头复现发现：**浏览器请求发到的是 http://YOUR_PUBLIC_HOST:9000（腾讯云旧系统）而非本地**
- 根因：`frontend/dong-ui/.env.production`（7-25 云端部署时创建）含 `VITE_API_BASE_URL=http://YOUR_PUBLIC_HOST:9000/api`，`npm run build` 将其烧入 dist；4173 preview 服务该产物 → 浏览器打云端旧代码（云端 dong-auth 未修 /me 403）；curl 直连 localhost 所以一直正常
- 修复：删除 `.env.production`（本地运行期），重建 dist，验证产物无云端地址；浏览器复测 login→/me→dashboard 全 200 且正确跳转
- 经验：**前端"后端地址"类问题先查 .env* 与构建产物**；云端地址此前由 .env.production 注入，未来若重新上云需重建该文件；验证浏览器行为可用 /tmp/pwtest/login-test.mjs（playwright-core + 系统 Chrome，无需下载浏览器）
