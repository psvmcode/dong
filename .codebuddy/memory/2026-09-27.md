## cache 模块加固：限流 + 降级 + 熔断

需求来自用户：缓存场景不能只顾 db 与缓存的数据维护，还要防恶意攻击，
以及服务不可用时的友好提示，不能「太无脑地保证每次都请求到数据」。

确认的方案（用户选择）：公共层 + 业务层都改；缓存与 DB 都不可用时优先返回过期旧值（带 stale 标记），
没有旧值才报 1005；四项防护全做（IP 读限流、扫描检测、单 key 回源频控、重接口单独限流）。

### 公共层 framework/cache
- `CacheLookup` 新增 Stale 态；`CacheEntry` 新增 `discardAtMillis`，形成「逻辑过期 + 宽容期」双时间
- 新增 `CacheCircuitBreaker`（CLOSED/OPEN/HALF_OPEN，进程内）与 `CacheResolution`（Fresh/Stale/Absent/Unavailable）
- `MultiLevelCache.resolve()` 成为主读路径，回源前三道闸门：熔断 → 全局 + 单 key 频控 → 重建锁
- **回源失败不再写空值标记**：原代码会把一次故障固化成「数据不存在」，是这里最严重的隐患
- L2 熔断下沉在 `RedisCacheStore` 内部，Redis 故障就地降级为 Miss，不把异常抛进读链路
- 重建锁拿不到（异常）时退化为无锁回源：锁只影响击穿保护，不该让 Redis 故障掐断正常读链路

### cache 模块
- `CacheReadGuard`：IP 读限流（令牌桶）/ 重接口配额（固定窗口）/ 撞 id 扫描封禁；
  Redis 不可用时全部降级到本地 Caffeine，限流器自身故障一律放行
- `CacheGuardInterceptor` 挂在 `/api/cache/**`，`afterCompletion` 里按异常码 1001 记 miss（1005 不算，
  否则下游抖动会把正常用户封掉）
- 响应语义：有旧值 → `stale=true` 且 message 提示；无旧值 → 1005；确认不存在 → 1001
- 布隆过滤器不可用/预热失败一律放行并 warn，不放大中间件故障
- `ClientIpResolver` 抽到 common/web，全局限流拦截器改为复用

### 配置
全部挂在 `dong.cache.*`：stale-grace、breaker-*、rebuild-global/key-limit-per-second、guard-*

### 验证状态
仅 `mvn -q clean compile` 通过，未启服务做端到端验证。

## 全站接口：GET 全部改为 POST

用户要求：项目中所有接口改为 POST，不要有任何 GET 请求。
确认的方案：查询参数也进 JSON body（不是只换注解），框架自带的 actuator 与 Knife4j 保持不变。

### 落地方式
- 103 个 GET 接口全部改为 `@PostMapping`，新增约 40 个查询 DTO（各模块 `dto` 包，手写成对的 getter/setter）
- 分页参数抽了公共基类 `com.dong.common.result.PageQuery`（pageNum/pageSize + 校验 + `toPageRequest()`），
  各查询 DTO 直接继承，避免每处重复写校验
- `@PathVariable` 保留在 URL 上，只把查询参数搬进 body
- 原有 POST/PUT/DELETE 接口的 `@RequestParam` 一律没动，改动严格限定在 GET 接口范围内

### 踩到的路径冲突（改 POST 后同路径撞车，必须重命名）
- `GET /accounts` → `POST /accounts/list`（`/accounts` 已被 POST 开户占用）
- `GET /fx/rate` → `POST /fx/rate/current`（POST /rate 是改牌价）
- `GET /settlement/batch` → `POST /settlement/batch/list`
- `GET /seckill/activities` → `POST /activities/list`
- `GET /remittance`（分页）→ `POST /remittance/page`
- `GET /cache/products`（分页）→ `POST /products/page`
- `GET /sign`（是否已签到）→ `POST /sign/status`

### 连带修改
- `CacheGuardInterceptor.isHeavy()` 原来靠「非 GET 即重量级」判定，全站 POST 后会把所有读请求
  拖进 20 次/分钟的重接口配额。改为只认 PUT/DELETE 与 warm-up、penetration、all 这几个路径
- 短链跳转 `/short-link/s/{code}` 原本是 GET + 302，改 POST 后无法再从浏览器地址栏发起，
  改为返回原始地址由调用方跳转（语义受损点，已告知用户）
- README 与 doc 中的接口表格、curl 示例同步改为 POST + body
