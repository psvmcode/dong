## 跨境支付代码审查 + 隐患修复 + 新场景（提交 208cef4，18 文件 +805）

### 修复的 6 个隐患
1. **锁获取未检查**：tryLock 拿不到锁也继续创建 → 现在检查 isAcquired()，失败抛 1002
2. **幂等冲突抛错**：唯一索引冲突返回 1002 → 捕获 DuplicateKeyException 返回已存在的单子
   （实测 aml-v2-1 重放返回原单 code=0）
3. **账户状态未校验**：冻结账户可汇款 → requireAccount 校验 status=1
4. **日限额不可回收**：扣款失败占用日额度 → 加 releaseDailyLimit（Lua math.max 防负数），
   debitAndPersist 失败时释放
5. **并发重复退款**：failAndRefund 无抢占 → 先 CAS 状态到 REFUNDED（乐观锁），成功才执行退款
6. **补偿消息风暴**：30 秒扫一次对在途消息也重发 → 加 2 分钟静默期（COMPENSATION_IDLE）

### 性能优化

- runtime 8 次 count → 一次 group by（countGroupByStatus 返回 List<Map>）

### 修复过程中发现的 3 个新 bug（都在 AmlMonitor）
1. **单位不匹配**：Lua 脚本收到分、申报线却是元（999900 < 9900 永假）→ 贴线计数永不生效。
   修：调用方统一换算成分传入
2. **重复乘 100**：脚本里 `amount * 100`，调用方已乘过 → 总额虚增 100 倍（2999700.00）。
   修：脚本直接用传入的分
3. **key 解析**：`substring(KEY_PREFIX.length())` 得到 `2026-09-03:1`，parseLong 失败。
   修：取 lastIndexOf(':') 之后
