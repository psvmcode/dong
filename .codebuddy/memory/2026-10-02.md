## 网页版 Agent 设计文档（未落地）

新增 `doc/scenario/agent.md`：`com.dong.agent` 模块的完整设计文档，对标 WorkBuddy，
定位为第 13 个实验场景「Agent 工程实验室」。已在 `doc/scenario/README.md` 登记。

关键决策（落地时不要改）：

- **零新增 Maven 依赖**：模型侧 JDK 21 `java.net.http.HttpClient` 流式读 SSE，
  页面侧 Spring MVC `SseEmitter`。不引 webflux（双栈 + reactor-netty），不引 Spring AI（机制要可见）
- **工具实现放 `support/tool`**，走进程内 service 调用，不 HTTP 回打自己的接口
  （回打会重复过 `GlobalRateLimitInterceptor`，还多一次超时与序列化）
- **五道停止闸门**：max-steps 12 / max-tool-calls 24 / run-timeout 120s / token 预算 120k / 连续失败 3 次；
  每次运行必须有 `finish_reason`
- **E1~E8 对照实验**默认跑 `mock` provider（可复现、离线、不烧钱），真实模型只作偏差观察
- **最大风险是 SSE 占用 tomcat 线程**（max 200）：对策是并发上限（1003）+ 墙钟超时 + `AgentRunCleanupTask`
- **页面不能用 `EventSource`**（只支持 GET，与全站 POST 冲突），改用 `fetch` + `ReadableStream` 手动解析
- 幂等键 `client_token` 必须 nullable：MySQL 唯一索引允许多 null、只允许一个空串，
  写成空串默认值会让所有未传 token 的运行互相撞唯一键
- 不提供任意 SQL / 命令 / 文件读写；`http.fetch`、`mysql.probe` 默认关闭（SSRF 与注入）

## 工具协议专题文档

追加 `doc/topic/agent-tool-protocol.md`（工具层纵向展开），已在 `doc/topic/README.md` 登记。
由此引出两处场景文档的同步修改：

- `agent_run.status` 增加 **5 等待确认**：L1 工具要挂起等用户确认，挂起态必须落库
  （只放内存的话进程重启后找不到该继续哪一步），确认超时按取消而非拒绝
- `dong.agent.tools.side-effect-confirm-timeout: 5m`

工具层三条硬约束：schema 是给模型的软约束，真正拦越界值的是实现里的硬校验；
工具内部必须捕获全部异常并回传（业务异常原样告知、未知异常只给笼统提示防泄露）；
DNS rebinding 挡不住，所以 `http.fetch` 靠默认关闭把风险面降到零，而不是靠判定逻辑。

## P0 落地完成（commit d72638c，已 push）

新增 `com.dong.agent` 全部骨架 + 五张表 + 单文件页面，实测跑通一轮。
远程库表已建（容器不重跑初始化脚本，`/tmp/AgentTableInit.java` + JDBC 单独执行）。

踩到并修掉的两个真实坑：

- **`finish_reason` 默认空串让枚举反解炸了**：MyBatis 默认 EnumTypeHandler 用 `valueOf`，
  空串抛 `No enum constant FinishReason.`。凡是「建记录时尚未赋值」的枚举字符串列都要写
  TypeHandler 把空串映射成 null（`FinishReason`、`MessageRole` 已加）
- **`CompletableFuture.orTimeout` 超时后 `get()` 抛的是 ExecutionException**，
  `catch (TimeoutException)` 编译不过——超时是「以 TimeoutException 结束 future」，
  要判断 `e.getCause() instanceof TimeoutException`

其它落地要点：

- 工具执行线程池与运行调度线程池**必须分开**（`agentToolExecutor` / `agentRunExecutor`），
  共用会让并发运行把池占满，表现为工具排不上队而循环又退不出来
- `AgentRunRecorder` 不是 bean（持有序号与推送出口，单例会串味），每次运行现场 new
- 引擎只编排不落库，落库与推流全走 `AgentRunListener`；
  监听器要带 `toolCallId`，否则工具结果无法与 assistant 消息对应
- 验证启动命令：`--dong.agent.enabled=true --dong.mariadb.enabled=false` 等
  （本地不装中间件，云上 MariaDB/ES/Mongo 未起时必须关掉，否则起不来）
- 库里现在有一条 status=1 的残留运行记录（首次失败留下的），
  正好说明 P3 的 `AgentRunCleanupTask` 为什么必须有
