# 2026-09-19

## 抢红包场景重构（并发 / 限流 / 降级 / 库存自愈）

- 新增 `red_packet_item` 份额表（packet_no + seq + amount + status + user_id），金额发红包时按份落库；
  Redis 队列元素由"金额"改为 `序号:金额`，队列降级为**可重建的副本**。已在远程 MySQL 建表（幂等 DDL）。
- Lua 脚本区分三种空：未预热(-2)、真的抢完(-1)、计数与队列不一致(-2)，重复抢(-3)；
  抢/归还两个脚本严格互逆，落库失败必须归还，否则份额凭空消失。
- 单用户滑动窗口限流（`GrabRateLimiter`，60 次/分钟）；**限流器自身不可用（Redis 故障）时放行**——
  拒绝会把中间件故障放大成业务全停，放行后还有 DB 唯一键兜底。
- Redis 整体不可用 → 降级 DB：随机序号起步选候选 + `status=0` 乐观锁占位，重试 3 次后抛 1002。
- 防超发：份额 `status=0` 占位 + `decreaseRemain` 带 `remain_count >= 1 and remain_amount >= 金额` 充足条件。
- **脏份额（占位失败）直接丢弃不归还**，否则会在队列里无限打转。
- 自愈：`RedPacketConsistencyTask`（5 分钟）以库为准比对并重建副本、纠正主表剩余、推进 FINISHED；
  新增 `POST /api/red-packet/rebuild` 与 `GET /api/red-packet/runtime`（限流/降级/重建/脏份额计数）。
- 配置新增 `dong.redpacket.*`：grab-limit-enabled、grab-limit-per-minute、stock-ttl、db-fallback-enabled、
  consistency-task-enabled、consistency-interval-ms、consistency-scan-limit。
