## 兜底加固收尾（commit 1aa8eac）

用户要求「挑不出任何毛病，任何特殊情况都能兜住」。本轮补了三类此前完全没管的：

1. **异常信息泄露（安全问题，本轮最重要）**
   `GlobalExceptionHandler.handleUnexpected` 原本把 `ex.getMessage()` 直接回给客户端。
   未预期异常的消息里可能含 SQL、表名、服务器文件路径、内网地址、第三方接口细节——
   直接回传等于把系统内部结构交给调用方。
   改为：完整堆栈只写日志，给客户端一个 **traceId**（UUID 前 12 位）。
   用户报障凭 traceId 定位，排查能力不降。**这是 500 类异常的标准做法。**

2. **@PathVariable 完全没校验**（此前只加固了 @RequestParam，属于明显不一致）
   10 个 Controller 补上：字符串 → @NotBlank @Size(128)；数值 → @Positive（channel 单独 @Min(0)@Max(99)）。
   实测 `/api/cache/products/-1` → 1000「必须是正数」；超长 orderNo → 「个数必须在0和128之间」。

3. **传输层兜底（application.yml）**
   - Jackson `stream-read-constraints`：max-string-length 200000、max-nesting-depth 32、max-number-length 50
     （挡超大 payload 与深度嵌套攻击）
   - Tomcat：`max-http-form-post-size/max-swallow-size` 2MB、`threads.max` 200、
     `connection-timeout` 20s、`max-keep-alive-requests` 100
     （挡超大 body OOM；限制工作线程，避免慢请求把线程池耗光导致整个服务无响应）

## 教训（已犯两次）

**改完先编译再提交**。本轮又犯：加注解没编译就 commit，缺 import 编译失败，
多出一个「补 import」的修复 commit。批量改注解后固定跑 `ensure_imports.py` 可避免。

## 容错加固全景（本次需求已完成项）

| 层 | 措施 |
|---|---|
| 参数 | 数值上下限、字符串非空/长度、金额精度、路径参数、枚举 |
| 安全 | **短链 SSRF**（协议白名单+内网拦截）、**异常信息脱敏 traceId** |
| 并发 | LockLab 乘积兜底（Controller 分别限 + Service 总量限） |
| 流量 | 全局 IP 令牌桶限流（排除 actuator） |
| 传输 | 请求体大小、嵌套深度、工作线程池上限 |
| 异常 | 全局 handler 覆盖 Business/参数/冲突/重复键/未预期 |
