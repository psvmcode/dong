### 关键设计
- `ad_event` 令牌与事件合一：`uk_trace_type` 防换 eventId 刷量，`uk_event_id` 防客户端重试；GSP 二价成交价由服务端签发进令牌，客户端不能传价格。
- CPC 只在点击扣费、CPM 只在曝光扣费；另一类事件仍写 0 元流水进报表，保证对账能重算 CTR。
- Redis Lua 预算闸门只是副本，返回配额不足时**不直接拒绝**而是切回 DB 条件更新裁定；DB 三道护栏（总预算 / 账户余额 / 日预算）按补偿链最短的顺序执行，失败反向补偿再写拒绝流水。
- `ad_daily_stat` 按 `stat_date` 分行，今日花费不进计划表，天然避开日切竞态；对账刻意不覆盖 `budget_cents` 历史快照。
- 对账任务以 `ad_charge_record` 为唯一权威源：重算日汇总、回写计划累计、重建 Redis 配额副本、补投超时 PENDING 事件；流水超 1000 条抛 1007 拒绝截断。
- MQ 坑：既有 `RocketMqListener` 只订阅 `demo-order-event`，新主题必须有自己的监听器，故加 `AdChargeRocketMqListener`（`@ConditionalOnProperty` 跟随 `dong.rocketmq.enabled`）；本地总线靠 `MessageHandlerRegistrar` 自动注册同一 handler。
- 降级链：Redis 挂→DB 条件扣减 / MQ 挂→同步计费 / 消息丢→对账补投；Controller 用 `@Value` + 1004，service impl **不加** `@ConditionalOnProperty`（避免 Bean 缺失）。
- 并发对照实验 `/api/ad/report/lab/burst` 强制同步计费，先串行预生成曝光、再并发点击，回读库内金额验证是否超投；实验模式豁免 200ms 最小点击间隔。
