## 新增 logging 模块：基于 ES 的 ELK 可视化日志检索

- 需求：基于项目运行日志，结合 ES 搭一套 ELK 式的可视化日志检索功能。
- 落地：`com.dong.logging`，接口 `/api/logs`，页面 `static/logs/index.html`，文档 `doc/scenario/logging.md`。
  采集（logback appender → 有界缓冲 → 定时批量写 ES）/ 补齐（落盘文件回填 + 行数位点续传）/
  存储（按天索引 + 读别名，过期整块删索引）/ 检索与可视化（Kibana 风格页面，无外部依赖）。
- 已提交并推送：`4a8f0e2 新增日志检索模块：基于 ES 的 ELK 可视化日志检索`。

### 关键决策（以后改动要保持一致）
- 缓冲是静态单例：appender 由 logback 创建，早于 Spring 容器，拿不到 Bean。
- 缓冲容量只能配在 `logback-spring.xml`（不在 application.yml）。
- 回填位点按**行数**记并存 ES；按日志时间归档到各自那天的索引（不能一律写今天）。
- 保留天数 14，与 logback `maxHistory` 对齐；过期整块删索引。
- 日志模块启动期不强依赖 ES（与 search 相反），建索引失败只退避告警。

## 新增 rpc 模块：极简 RPC 轮子

- 需求：写一个简单 RPC 轮子用于模块间通信，最好用 protobuf。
- 与用户确认后的方案（四项选择）：跨进程真 RPC（本机 9090 + 真实 TCP，进程内自调用作对照）、
  零依赖自研 protobuf wire format、Netty、**只做服务注册与发现**（不做重试/熔断/异步/可视化页面）。
- 落地：`com.dong.rpc`（annotation/codec/protocol/transport/registry/support/task/api/dto/demo/controller），
  跨模块示例 `ProductQueryService` 实现在 search 模块。文档 `doc/scenario/rpc.md`。
- 已提交并推送：`5c2ac94 新增 RPC 框架模块：自研 protobuf 协议 + Netty + Redis 注册发现`。

### 关键技术事实（以后改动要保持一致）
- netty 4.1.119 随 redisson 传递进入 classpath，pom 已显式声明（版本一致，无新 jar）。
- protobuf 不在依赖里、本地无 protoc，所以协议是自研；整型统一 zigzag。
- 注册发现用 Redis ZSet（score=心跳时间），客户端本地缓存 5s，空结果不缓存，Redis 挂了降级到配置地址。
