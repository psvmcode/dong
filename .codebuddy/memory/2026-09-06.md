- 观察到的启动期 ERROR（**非缺陷，勿误判**）：`dong-hikari - Error thrown while acquiring connection
  from data source` + `SQLNonTransientConnectionException: No operations allowed after connection closed`。
  触发链：`TccRecoveryTask.recover()`（`initialDelay=20_000` 已配，故是启动后第 20 秒）→
  `TccCoordinatorServiceImpl.recoverPending()` → `DataSourceTransactionManager.doBegin()` →
  `HikariDataSource.getConnection()` → `HikariPool.<init>` 的 `checkFailFast`。
  根因：HikariCP **懒加载**，首次 getConnection 才建池，恰好撞上远程 MySQL 瞬时抖动。
  判据：两条 ERROR 同秒发生、之后 6 分钟不再新增、health 仍 UP → 一次性抖动，应用自愈，无需改代码。
  ➜ 排查同类问题的思路：看 ERROR 是否**持续增加**，而不是看有没有；瞬时一条且随后健康就不算故障。
- **顺带修复一个真实缺陷**：`GlobalExceptionHandler` 的 `@ExceptionHandler(Exception.class)` 兜底
  把 Spring 的 `NoResourceFoundException` 也捕获了，导致静态资源 404 **被升级成 500** 并打印堆栈。
  修法：改为 `@RestControllerAdvice(basePackages = "com.dong")`，只管业务 Controller，
  Spring 内部异常交还框架自己处理。验证：/nope.png 与 /api/nothing 均恢复 404，
  favicon.ico 200，业务异常（同币种汇款、空参数）仍正确返回 code=1000。
  ➜ 教训：`@RestControllerAdvice` **不加 basePackages 时会吞掉 Spring 内部异常**，
  把 404 变成 500，是监控告警和客户端判断的隐形坑。
- 新增 `src/main/resources/static/favicon.ico`（commit d211962，180 字节，深蓝底+白色 D，32×32 PNG-in-ICO）。
  背景：`NoResourceFoundException: No static resource favicon.ico` 是**浏览器自动请求**触发的运行时 404，
  不是启动失败，也与改名无关（改名前的日志里同样有）。curl 不会触发，只有浏览器打开页面才会。
  Spring Boot 3.2+ 会为此打印完整堆栈，看着像崩溃，实际已被处理成 404，功能无影响。
  **知识点**：浏览器"自动请求 /favicon.ico"无法关闭（IE5 遗留约定），但可用 HTML 的
  `<link rel="icon">` 引导到别处（优先级高于默认路径）；`href="data:,"` 可做到零请求。
  因 Knife4j 的 doc.html 在 jar 内不好改，本项目选择直接放静态文件，一次放置全站生效。
  生成方式：python3 手工构造 PNG（zlib+struct）再包成 ICO，无需 PIL。
