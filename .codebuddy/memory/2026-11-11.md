# 2026-11-11

## 全站按 dong-standards 规范审查与修复

用户要求"整体看后端是否严格按 skill 写,优化后推送"。做法:Python 脚本机械扫描 560 个 Java + 39 个 mapper XML,配合只读 code-explorer 子代理审查分层/注解/SQL(3 个里 2 个超时,1 个给出 109 处确定违规)。

### 已修(34 个后端文件 + 5 个前端 api 文件)
- **接口全 POST**:8 处 DELETE/PUT 改 POST;同路径已有 POST 的加动作后缀(`/delete`、`/update`、`/cancel`),dong-web 的 5 个 api 文件同步改路径与函数名(deleteQuery/putJson → postQuery/postJson)
- **定时任务**:10 个方法体补整体 try/catch(调度线程吞异常),2 个任务类补 `@ConditionalOnProperty(matchIfMissing=true)`
- **注解/事务**:13 个主库写方法补 `@Transactional(rollbackFor = Exception.class)`;15 处字段/常量 Javadoc 从 `xxx。` 改成按角色说明
- **异常格式**:MathTool 4 处中文 `IllegalArgumentException` → `BusinessException(Constants.CODE_PARAM_INVALID, 英文短句)`
- **取值越界/全量截断**:collect/recent/generate 4 处按 MAX_BATCH_SIZE/MAX_QUERY_LIMIT 封顶;seckill.activities、replica.findAll 两处全量查询截断 + log.warn
- **格式**:8 处方法体内空行删除

验证:`mvn -q clean compile` 通过 → 启动 Spring(Started DongApplication,无 Ambiguous mapping/BeanCreationException)→ curl 5 个改造后路径均返回业务响应 → 立即关闭并确认 8090 释放;dong-web `npm run build` 通过。

### 明确未修(附理由,后续可按模块推进)
- **645 处 `@param`/`@return` 缺失、51 处 SQL 语句中文注释、64 处 DTO 手写 getter/setter 未转 @Data、35 处方法 Javadoc 缺失**:机械补全只会生成空洞注释或大范围改动手写 DTO,违背"注释写为什么"且风险高,列为历史技术债
- **包职责 2 处**(AgentRunRecorder 放 service/impl、MqFacade 实现留 framework 本包):跨包移动牵连大量 import,本轮未动
- **脚本误报纠正**:`文件末尾空行 560 处`(项目统一 `}\n`)、`方法体内空行 5513 处`(把类体/lambda 算进去,实际 8 处)、`类缺 Javadoc 68 处`(Javadoc 超过 12 行窗口)、`service impl 缺注解 86 处`(长 Javadoc 把注解推出检查窗口)、`集合返回 null 1 处`(toLocation 返回"无坐标"语义)——均非违规
- **`@ConditionalOnProperty` 5 处缺失(子代理建议)未采纳**:agent/upload 的 Controller 直接注入 service 并 `@Value` 显式返回 1004,加注解会导致 Bean 缺失、启动失败(agent 默认 false)。见 MEMORY.md
