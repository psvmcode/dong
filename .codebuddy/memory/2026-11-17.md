# 2026-11-17

## 全项目服务端错误风险排查与修复

- 用户要求：纯代码层面分析，不启动项目、不跑测试，修复可被真实触发的 500 / OOM / 资金库存数据错乱，直到没问题。
- 方法：5 个并行只读子代理分组扫描 common/config/framework、cache/classic/seckill/redpacket、search/logging/rpc/agent、crossborder/order/tcc/mq/replica/doc/social、upload/ad，得到约 30 条真实缺陷，逐条修复并多轮编译验证。

### 高危修复
- **ad**：Mapper 漏 `daily_limit_cents` 导致 update-limit 稳定 NPE 500；`BurstLabRequest.userId` 显式 null 拆箱 500；熔断器半开探针失败后永久不恢复；计费消息漏校验 eventType；召回缓存固定 global key 导致部分计划永远拿不到流量；点击窗口 long 溢出。
- **framework**：缓存类型不匹配反序列化抛 5000 → 按 Miss 自愈；失效广播加 try/catch；`LockHandle.unlock` 捕获所有 RuntimeException；tryLock / Lua 限流 / Kafka 同步异常转业务码 1005；缓存重建中断不再无锁回源。
- **replica**：转账由读后写绝对值更新改为 DB 原子条件扣减/增加，消除并发丢失更新。
- **crossborder**：畸形清算消息确认消费避免毒消息堵死顺序队列；对账加事务 + 金额 null 归一；锁汇后扣款失败释放报价；渠道配置金额 null 兜底。
- **redpacket**：DB 降级路径不归还未弹出的 Redis 份额（幽灵份额）、脏份额 claim 失败归还、Lua 内脏元素放回队列、remainCount 拆箱 NPE、对账 Integer 比较 NPE。
- **seckill**：prepare 冲突补偿 Redis 预热、unitPrice 与起止时间 null 守卫。
- **order**：REFUND_SUCCESS 服务端金额守卫 + DTO `@DecimalMin` + 状态机守卫。

### 可用性与边界
- ad / upload 清理任务加分布式锁；agent SSE 发送串行化；E8 父任务独立线程池避免同池饥饿自锁；LLM 流加限额输入流防 OOM；shortlink 缓存带状态快照；UV 合并 key 加 UUID；GEO 空集提前返回；search / logging 参数错误透传 1000 而非包装 1005；CacheReadGuard 在 expire 失败时清理无 TTL key。
