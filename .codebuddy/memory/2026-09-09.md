每篇统一结构：一句话 → 机制 → 记忆口诀表格（用户偏好「通俗易懂、说重点」）。
各篇核心结论：
- index：B+ 树胜出因「矮胖+叶子链表」（3层可存2000万行）；**行锁加在索引上，没索引≈锁全表**
- transaction-isolation：InnoDB 默认可重复读（Oracle/PG 是读已提交）；脏读=读未提交，不可重复读=同row被改，幻读=行数变
- mvcc：快照读不加锁；**两级别唯一差异是 ReadView 生成时机**（RC 每次生成，RR 只生成一次）
- lock：临键锁=记录锁+间隙锁，用于防幻读；**隐式类型转换会让索引失效导致锁全表**（varchar 字段传数字）
- explain：type 优劣 system>const>eq_ref>ref>range>index>ALL；Extra 的 Using filesort/temporary 是红灯

**Java 并发七篇已全部写完**（commit 445f726，共 1355 行）：
volatile(182) + synchronized(159) + cas(198) + aqs(168) + threadpool(199) + threadlocal(199) + concurrenthashmap(223)。
建议顺序 volatile → synchronized → cas → aqs → threadpool → threadlocal → concurrenthashmap
（前四篇递进：可见性 → 补原子性 → CAS 是轻量手段 → AQS 用 CAS 搭起 JUC）。
各篇核心结论：
- synchronized：锁在对象头 Mark Word；升级**只升不降**；**偏向锁 JDK15 起废弃默认关闭**（JEP 374，答题时提这点显跟得上版本）
- cas：一条 CPU 指令 cmpxchg；ABA 用 `AtomicStampedReference` 版本号；高并发计数用 `LongAdder` 而非 AtomicLong
- aqs：`volatile int state` + FIFO 双向队列 + 模板方法；**默认非公平**因唤醒挂起线程开销大、让新线程插队吞吐更高
- threadpool：**队列满了才建临时线程**（最易记反）；maximumPoolSize 只在队列有界时才有意义；
  不用 Executors 是因无界队列/无限线程→OOM；拒绝策略别用 DiscardPolicy（静默丢任务）
- threadlocal：数据存在**线程自己**的 map 里（ThreadLocal 只是 key）；泄漏根因是**线程长期存活+value强引用**，
  弱引用只是让 key 变 null，非根因；线程池里更直接的坑是**数据串了导致越权**
- concurrenthashmap：1.7 分段锁 → 1.8 CAS+synchronized 锁单桶；读无锁靠 volatile；**key 和 value 都不许 null**（避免二义性）

首篇：`doc/learning/java/volatile.md`——可见性 + 禁止重排序，
重点澄清「**不保证原子性**」这一高频误解，并给出判断标准：
**写操作是否依赖变量当前值**（不依赖→volatile 够；依赖如 count++→用 Atomic/synchronized）。

各篇核心结论（易错点）：
- dynamic-proxy：JDK 要求**接口**，CGLIB 靠**继承**（不能代理 final）；**JDK8 后 JDK 代理更快**（"CGLIB 更快"是过时说法）；
  Boot 2.x 起默认 CGLIB（因 JDK 代理只能转接口类型易踩 ClassCastException）
- JMM：与「堆栈分区」是两回事；happens-before 是**因果不是时间**；volatile 靠**内存屏障**
- GC：可达性分析（非引用计数）；新生代**复制**、老年代**标记整理**；G1=分 Region 挑垃圾最多的先收
- classloader：**先向上委托再向下尝试**；核心目的是**保护核心类库不被篡改**；打破靠 TCCL（JDBC/SPI）
- redis 持久化：RDB 快照/AOF 命令日志；4.0+ **混合持久化**=RDB全量+AOF增量；**持久化≠备份**（救不了 flushall）
- 缓存：穿透=不存在的数据/击穿=单热点过期/雪崩=大量同时过期；**先改库再删缓存**（删而非改，避免并发顺序错乱）
- 分布式锁：`SET NX PX`+唯一value+Lua解锁；**看门狗续期**；Redlock 有 GC/时钟争议；**资损场景靠唯一索引兜底**
- spring 事务：靠**AOP 代理**，失效主因是没走代理（同类 this 调用）；默认只回滚 RuntimeException → **一律加 rollbackFor=Exception.class**
- bean 生命周期：构造早于注入（构造里用不了 @Autowired 字段）→ 用 **@PostConstruct**；**AOP 代理在初始化最后的 BeanPostProcessor**
- 循环依赖：三级=成品/半成品/**工厂**；**必须三级是为延迟决定返回原始对象还是 AOP 代理**；
  构造注入无解（实例化时就要依赖）；**Boot 2.6 起默认禁止循环依赖**
