# 2026-09-11

## 全站接口参数加固（commit 24facdc，25 文件 +480/-128）

用户要求「不信任任何接口参数，做好所有兜底」。

### 发现的最危险问题：短链 SSRF（真实漏洞）

`ShortLinkController.create(url)` 的 url 完全没有校验。短链跳转是服务端下发
`Location` 让浏览器访问，不限制目标就能构造指向内网的短链 → **SSRF**。
已修：`ShortLinkServiceImpl.validateOriginUrl()` 做**协议白名单**（只放行 http/https）
+ **内网拦截**（localhost / 回环 / 链路本地 169.254.0.0/16 含云元数据 / 私有网段）。
实测拦截 169.254.169.254、127.0.0.1、file://、javascript:、ftp: 全部生效。

### 加固手段

1. `Constants` 新增通用上限：MAX_BATCH_SIZE(1000)、MAX_THREADS(200)、MAX_LOOPS(500)、
   MAX_QUERY_LIMIT(200)、MAX_NAME_LENGTH(128)、MAX_TEXT_LENGTH(4096)、
   MAX_DELAY_SECONDS/MAX_WINDOW_SECONDS(86400)
2. 两个 Python 脚本批量给 20+ Controller 加约束（`/tmp/harden_params.py` 数值、
   `/tmp/harden_strings.py` 字符串），再 `/tmp/fix_indent.py` 修正注解缩进
3. **Service 层兜底**：`LockLabServiceImpl` 加 MAX_TOTAL_TASKS=20000。
   理由：Controller 校验可被内部调用绕过，且**两个参数分别受限≠总量受限**
   （200×500=100000，单独看都合法）。实测乘积超限被正确拒绝。

### 踩坑

- 批量脚本的正则 `@RequestParam\(([^)]*)\)` 匹配不到**无括号**的 `@RequestParam String x`，
  第一次漏掉 userId/code/url/member 等最该管的参数 → 改成 `(\([^)]*\))?`
- 脚本插入注解时缩进取的是「@RequestParam 与类型之间的空白」，单行时只有 1 个空格，
  导致注解缩进错位 → 需单独跑 fix_indent.py 按上一行缩进对齐
- 判定「已有约束」不要只看单行，要回看前 120 字符，否则会重复加注解（@Min 不可重复 → 编译错）

### 续：三项收尾（commit b1a643a ~ 067329d）

1. **金额参数**：`CrossBorderSettlementController` 的 perTxLimit/fixedFee/rateFee
   此前**完全无约束**（可传负数、可传 1e999）。已加 @NotNull @PositiveOrZero @Digits
   （费率 fraction=6，金额 fraction=2）。`CrossBorderAccountController.balanceDiff` 的 initial 加 @Digits
2. **DTO 金额字段**：4 个 Request 的 BigDecimal 只有 @DecimalMin 下限、**没有上限和精度**。
   已统一加 `@Digits(integer = 16, fraction = 2)`（order/order-fire、product-save、seckill-activity）
3. **全局限流**：新增 `common/web/GlobalRateLimitInterceptor` + `config/WebMvcConfig`。
   按 IP 令牌桶，默认 200 QPS，只拦 `/api/**`（**排除 actuator**，否则健康检查被限流会让监控误判），
   用**本地限流而非分布式**——保护性措施不该再依赖 Redis，否则 Redis 抖动时限流先失效。
   配置项 `dong.global-rate-limit.{enabled,permits,window-seconds}`。
   实测 permits=10 时连发 25 次 → 19 通过 6 个 1003 ✓
